# Research project release gate

## Scientific integrity

- [ ] A bounded question and falsifiable endpoint are written before the result.
- [ ] Data version, provenance, exclusions, and unit of inference are explicit.
- [ ] Confirmatory, sensitivity, and exploratory analyses are visually distinct.
- [ ] Uncertainty and negative or qualified results are first-class outputs.
- [ ] The boundary states what the result does not establish.
- [ ] Every public value can be traced to code or a machine-readable artifact.

## Interface and identity

- [ ] Canonical Lab Notes tokens and research-cycle mark are present.
- [ ] The site follows question → evidence → finding → boundary.
- [ ] The discipline accent passes WCAG AA where it carries meaning or text.
- [ ] Keyboard navigation, focus, reduced motion, and narrow/mobile layouts are tested.
- [ ] Illustrative or simulated graphics are labelled; they are never presented as measured data.
- [ ] Site, repository, report, protocol, source data, licence, and citation are mutually linked.

## Engineering and release

- [ ] Unit, integration, accessibility, security, and build checks pass.
- [ ] Generated output, credentials, local environments, and raw third-party data are excluded.
- [ ] README, repository description, topics, homepage URL, and release notes agree.
- [ ] Semantic version and changelog reflect the public change.
- [ ] The live deployment is visually checked after release.
